# 읽기 전용 파일 수집과 서버 연결

Windows·macOS·Linux 앱에서 **로컬 수집 → 폴더 선택 후 수집**을 누릅니다. 선택 폴더 아래 PS1·BAT·CMD·SH·BASH의 메타데이터와 SHA-256을 읽습니다. Windows에서는 Go COM API로 예약 작업 설정도 읽습니다. 파일 수집과 서버 검사는 읽기 전용이며 셸 실행기가 필요하지 않습니다.

## 연결 범위

Windows 작업 연결은 실행 파일에 직접 지정한 PS1·BAT·CMD, powershell.exe·pwsh.exe의 명시적인 -File, cmd.exe /c의 단순 BAT·CMD 호출과 call을 지원합니다. 상대 경로는 명시적인 절대 작업 폴더가 있을 때만 해석합니다. 환경 변수와 동적 표현식, -Command·-EncodedCommand, 암묵적인 작업 폴더와 복합 명령은 추측하지 않습니다. Shell 파일의 범위는 인벤토리, SHA-256 및 Windows의 SMB 파일 연결입니다.

같은 파일을 가리키는 여러 작업·동작을 보존하며 상세 패널에서 계정·로그온 방식·실행 파일·작업 폴더·최근 실행 시각·결과 코드를 확인합니다. 추가 작업 이름으로도 검색할 수 있습니다. 직접 참조를 찾지 못한 파일을 미사용 파일로 판단하지 않습니다.

예약 작업의 정의는 저장된 설정이며 실제 실행 환경 관측값이 아닙니다. 수집만으로 환경 비교 쌍을 만들지 않으며, 최근 결과 코드도 업무 성공·실패의 확정 진단으로 바꾸지 않습니다. 첫 수집 결과의 스크립트 상태는 미확인입니다.

## 제한과 중단

| 항목                      | 기본 제한                                  |
| ------------------------- | ------------------------------------------ |
| 스크립트 / 전체 탐색 항목 | 500개 / 25,000개                           |
| 파일별 / 전체 해시 읽기   | 16 MiB / 256 MiB                           |
| 예약 작업 탐색            | 5,000개, 폴더 512개·깊이 32                |
| 파일별 작업 참조          | 8개                                        |
| 결과 JSON                 | 2 MiB                                      |
| 수집 시간                 | 폴더 선택 후 45초, 개별 읽기 사이에서 확인 |

Windows 로컬 수집은 일반 로컬 고정 디스크를 대상으로 합니다. 모든 플랫폼에서 수집 중 발견한 링크를 제외합니다. 권한 부족, 수집 중 파일 변경, 지원하지 않는 동적 호출과 용량 제한은 종류별 건수로 기록합니다. 해시 수집에 실패하면 빈 값으로 두고, 큰 결과는 뒤쪽 항목을 제외해 다시 열 수 있는 부분 결과를 보존합니다.

중단 요청은 현재 읽기가 반환되는 시점에 적용됩니다. 개별 COM 호출을 강제 종료하는 하드 타임아웃은 제공하지 않습니다. 확보한 결과는 중단 상태로 표시하며 저장할 수 있습니다. 폴더 선택만 취소하면 기존 결과를 유지합니다. 관리자 권한을 자동 요청하지 않습니다.

## Windows SMB 공유

1. **서버 연결**에서 별칭과 `\\ops.example.test\scripts` 같은 신뢰할 수 있는 UNC 공유를 등록합니다.
2. **연결 테스트**로 현재 Windows 세션에서 공유 폴더의 목록을 읽을 수 있는지 확인합니다. 빈 폴더도 성공으로 표시합니다.
3. 스크립트 상세의 **서버 파일 연결**에서 공유와 `daily/backup.sh` 같은 상대 파일 경로를 저장합니다.
4. **읽기·SHA-256 확인**으로 연결된 일반 파일을 읽고 해시를 확인합니다. 파일별 해시 한도는 16 MiB입니다.

공유 별칭과 연결 경로는 앱의 로컬 설정에 보관합니다. 자격 증명은 Windows 세션에서 처리합니다. 검사는 버튼을 눌렀을 때만 요청하며 읽기 전용입니다. 서버 파일 경로는 등록한 공유 폴더 아래에서 해석합니다. 공유 검사 결과와 서버 파일 해시는 화면에 표시합니다.

검사 화면은 최대 10초 동안 응답을 기다립니다. Windows에서 진행 중인 읽기가 끝날 때까지 다음 검사 요청을 제한합니다. SHA-256은 읽은 파일의 지문이며, 파일을 실행할 예약 작업 계정의 권한은 별도로 확인해야 합니다.

## 스냅샷 형식

기존 schemaVersion 1은 계속 읽으며 수집 결과는 명시적으로 schemaVersion 2를 사용합니다. v1만 지원하는 이전 앱은 v2를 열 수 없습니다. 두 형식 모두 최대 2 MiB입니다.

- collection: 선택 root, 시작·완료 시각, complete·partial·cancelled 상태, 예약 작업 조회 상태·건수, 제한·실패 코드와 건수
- scripts[].sha256: 수집에 성공한 소문자 64자리 SHA-256
- scripts[].taskLinks[]: 작업 이름·동작 번호, 실행 파일·작업 폴더·계정·로그온 방식·최근 실행 시각·결과 코드
- scripts[].taskName: 기존 목록과 비교 참조에 쓰는 첫 작업 이름

스크립트 원문과 작업 인수는 저장하지 않습니다. 인수는 직접 참조를 해석하는 동안 메모리에서만 읽습니다. 오류에 가져온 원문이나 네이티브 오류 문자열을 노출하지 않습니다. 호스트·계정·경로 자체도 내부 운영 정보이므로 실제 결과를 공개 저장소에 넣지 않습니다.

fixtures/collected-workspace.json은 화면·검증용 합성 예제입니다. Shell 파일에는 engine 값 Shell을 사용합니다. macOS·Linux의 수집 결과는 예약 작업 조회 상태를 not_applicable로 표시합니다. [검증 기록](verification.md)
