# 개선 우선순위

현재 공개 단계는 실행 환경 비교 GUI와 Windows 읽기 전용 수집을 제공하는 초기 프로토타입이다. 1순위 수집기의 폴더 탐색·해시·예약 작업 직접 참조·부분 결과를 구현했다. 다음 우선순위는 실제 수동·예약 실행 환경 프로브다. v0.1.0이라는 패키지 버전이 MVP의 모든 기능 완료를 뜻하지 않는다. 계획은 [MVP 기획서](MVP.md), 구현과 검증은 [README](../README.md)와 [검증 기록](verification.md)을 따른다.

| 순서 | 개선                          | 완료 판단 기준                                                                                                                                                               |
| ---- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | Windows 읽기 전용 자산 수집   | 선택 폴더의 PS1·BAT·CMD와 예약 작업의 직접 참조를 연결한다. 파일 해시, 수집 시각, 권한 부족과 부분 실패를 보존하고 원본 파일·작업을 변경하지 않는다.                         |
| 2    | 실제 수동·예약 실행 환경 수집 | 수동 기준과 별도 진단 작업의 계정·엔진·비트 수·작업 폴더·모듈 경로를 같은 형식으로 얻는다. 원본 업무 스크립트를 실행하지 않고 재현하지 못한 조건은 미확인으로 표시한다.      |
| 3    | OS별 빌드와 설치 실증         | macOS arm64·amd64와 Ubuntu에서 컴파일, 설치, 네이티브 파일 대화상자, 저장 후 다시 열기를 확인한다. Windows Server·RDP·DPI도 지원 표시 전에 검증한다.                         |
| 4    | 진단 품질과 데이터 계약       | 상대 경로·엔진·모듈 경로 차이의 합성 재현 사례와 JSON 스키마를 공개한다. 관측한 차이와 원인 후보를 구분하고 자동 수정하지 않는다.                                            |
| 5    | 서버 기준본 비교와 보고서     | 사용자가 고른 기준본과 파일 해시·설정 차이를 비교한다. 공유용 내보내기에서 호스트·계정·경로의 익명화 미리보기를 제공한다.                                                    |
| 6    | 경량화 측정                   | 같은 합성 데이터와 장비에서 시작 시간, Go와 WebView 전체 프로세스의 메모리·CPU, 1천 개 자산의 검색·비교 반응 시간을 기록한다. 실행 파일 크기만으로 경량성을 판단하지 않는다. |

가장 먼저 검증할 사용 사례는 “직접 실행하면 성공하지만 예약 작업에서는 상대 경로 때문에 실패하는 스크립트”다. 수집한 작업 폴더 차이, 관련 파일 참조, 추가 확인 방법까지 연결되는 것이 첫 실용성 기준이다.

자체 스케줄러, 자동 재실행, 비밀번호 저장소와 원격 배포는 초기 우선순위에 포함하지 않는다. 기존 실행 도구와 함께 사용하는 진단 역할에 집중한다. 공개 다운로드용 macOS 패키지는 Developer ID 서명·공증, Windows 패키지는 코드 서명과 설치 경험을 별도로 검증한다.
